# Milliy Dastur — tayyor hosting paketi

В архиве `index.html` — весь интерфейс сайта в одном HTML-файле (CSS и JavaScript встроены). React/Vite/npm для публикации этой сборки не нужны.

## Что включено
- `index.html` — исходный готовый сайт, встроенные стили и скрипты; кнопки экспорта/скачивания самого сайта скрыты.
- Отдельная кнопка **Kurator kabineti** с входом через Supabase Auth.
- Шаблоны настроек Vercel, Netlify и GitHub Pages.
- `supabase/schema.sql` — таблицы материалов, клубов, настроек доступа и попыток тестирования, RLS-политики, приватный Storage bucket.
- `SUPABASE_SETUP.md` — инструкция настройки Supabase.
- `.env.example` — напоминание о публичных параметрах Supabase (для статической сборки их можно ввести в кабинете куратора; ключ service_role никогда не вставлять в браузер).

## Быстрый запуск на Vercel
1. Распакуйте архив и загрузите файлы в GitHub repository.
2. В Vercel нажмите **Add New → Project**, выберите репозиторий и нажмите Deploy. Build command не нужен; сайт — статический `index.html`.
3. В Supabase создайте проект и выполните `supabase/schema.sql` в SQL Editor.
4. В Supabase → Authentication создайте пользователей-кураторов и назначьте роль `curator` через доверенный серверный процесс в `app_metadata.role`. Для администратора используйте `admin`.
5. Откройте сайт, нажмите **Kurator kabineti**, введите Project URL и anon/publishable key, затем email/пароль пользователя.

## GitHub Pages
Включите GitHub Pages через **Settings → Pages → Build and deployment → GitHub Actions**. Workflow из `.github/workflows/deploy-pages.yml` опубликует корневой `index.html`.

## Supabase — важное
- В браузере разрешён только `anon` / publishable key. **Никогда не используйте `service_role` key на клиенте.**
- Не назначайте роли через `user_metadata`: пользователь может менять его сам. Роль проверяется из `app_metadata.role`.
- В текущем HTML-пакете кабинет куратора проверяет вход через Supabase Auth, но переключатели доступа и список прикреплённых материалов пока сохраняются в `localStorage` этого браузера. Они НЕ являются глобальными настройками и НЕ загружают файлы в Supabase Storage. Для реального многопользовательского управления нужно подключить операции CRUD к таблицам и Storage. SQL-схема подготовлена, но это не означает, что вся платформа уже переведена на серверное хранение.
- Основное приложение из предоставленной сборки сохраняет прежнюю логику данных. Изоляция данных учеников на сервере требует использования Supabase Auth и RLS для каждого запроса.

## Проверка
Откройте `index.html` локально или разверните его на статическом хостинге. Для входа в кабинет нужна активная сеть, настроенный Supabase проект и созданный аккаунт с ролью `curator` или `admin`.
